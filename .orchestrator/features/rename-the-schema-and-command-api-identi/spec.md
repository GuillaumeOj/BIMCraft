# Rename the schema and command API identifiers to Fabrilo

Issue [#384](https://github.com/GuillaumeOj/BIMCraft/issues/384), sub-issue of the epic [#380](https://github.com/GuillaumeOj/BIMCraft/issues/380) "Rename BIMCraft to Fabrilo". Requirement IDs: none. Milestone: Phase 1 – MVP.

The rule to follow is [ADR 0028](../../../docs/dev/adr/0028-rename-to-fabrilo.md) "Rename to Fabrilo". The issue says "ADR 0025": the record was renumbered 0028 when it merged, its content is the one the issue means. Schema and API URNs: `urn:bimcraft:…` becomes `urn:fabrilo:…`. No compatibility is kept: nothing accepts the old URNs.

## 1. Scope

| File | Change |
| --- | --- |
| `crates/api/src/schema.rs` | `ID` `urn:bimcraft:api` → `urn:fabrilo:api`; title `BIMCraft command API` → `Fabrilo command API` |
| `crates/schema-gen/src/json_schema.rs` | title `` BIMCraft `<ns>` schema `` → `` Fabrilo `<ns>` schema ``; doc comment example `urn:fabrilo:schema:core` |
| `crates/schema-gen/tests/json_schema.rs` | `$id` values `urn:fabrilo:schema:sample` and `urn:fabrilo:schema:core`, and the assertion on `$id` |
| `crates/schema-gen/tests/snapshots/sample.schema.json` | regenerated |
| `schema/core/api.schema.json` | regenerated (`UPDATE_SNAPSHOTS=1 cargo test -p schema-gen`) |
| `schema/api/protocol.schema.json` | regenerated (`UPDATE_SNAPSHOTS=1 cargo test -p api`, after the core schema) |
| `docs/reference/schema/*.md` | regenerated by the same schema-gen run; today they carry no URN or title, so no change is expected |
| `docs/reference/book.toml` | title `Fabrilo Reference`, authors `["Fabrilo contributors"]` |
| `docs/reference/introduction.md` | product name BIMCraft → Fabrilo (two mentions). Not listed in the issue, but the book is retitled here and no other sub-issue owns `docs/reference/` |
| `docs/dev/api.md` line 32 | the URN only: `urn:bimcraft:api` → `urn:fabrilo:api`, so that the acceptance criterion "no `urn:bimcraft` left" holds. The other BIMCraft mentions of `docs/dev/` belong to #388 |
| `ui/src/api/` | nothing references the URNs today (checked with `git grep`). `ui/src/api/protocol.gen.ts` is regenerated with `bun scripts/generate-api-types.ts` to prove it: no diff is expected, because titles and `$id` are not emitted |

**Out of scope** (other sub-issues of #380): the `bimcraft/<name>` material keys in `crates/api/src/*/tests.rs` and the material crate (#382), `BIMCRAFT_BLESS` (#382), UI strings and the `bimcraft.language` key (#386), `docs/dev/` beyond the one URN (#388), the guard (#389).

## 2. Where `urn:bimcraft` may remain

The acceptance criterion "no `urn:bimcraft` left in the repository" excludes, as ADR 0028 allows:

- `docs/dev/adr/0028-rename-to-fabrilo.md`, the record of the change (its "Old" column);
- `.orchestrator/features/*` records of earlier features (orchestrator working files; #388 and #389 decide their fate).

Check: `git grep -n "urn:bimcraft" -- ':!docs/dev/adr/0028-rename-to-fabrilo.md' ':!.orchestrator'` prints nothing.

## 3. Acceptance

1. The check in section 2 prints nothing.
2. Reproducible: after the regeneration is committed, `UPDATE_SNAPSHOTS=1 cargo test -p schema-gen` and `UPDATE_SNAPSHOTS=1 cargo test -p api` leave `git status` clean, and plain `cargo test -p schema-gen -p api` passes.
3. `cargo llvm-cov -p api -p schema-gen --all-features --fail-under-lines 98` passes.
4. `mdbook build docs/reference` passes, and the built book's title is "Fabrilo Reference".
5. `cargo clippy -p api -p schema-gen --all-targets --all-features -- -D warnings`, `cargo fmt --all --check`, `scripts/check-all.sh repo` are clean.
6. From `ui/`: `bun scripts/generate-api-types.ts` (run from the repository root) leaves no diff; `bunx vitest run src/api` passes.
7. Commits: Conventional Commits, signed off, `Refs #384`, no `wip` subjects. The pull request states "User docs: N/A (developer reference)" and closes #384.

## 4. Tasks

1. **back** — the whole rename and regeneration (section 1), with the checks of section 3 (1 to 6). One task: the files are few and the regeneration order (schema-gen, then api, then the TypeScript types) must stay in one branch.
2. **front** — reviews task 1 (the `ui/src/api/` client and the generated `protocol.gen.ts`), through the review request back sends. No separate frontend task: there is nothing to change in the UI.
